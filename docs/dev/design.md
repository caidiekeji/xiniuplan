# 设计规范

本文档定义云枢面板的设计系统，包括设计原则、Design Token、组件规范、布局规范和交互规范，确保产品视觉和体验的一致性。

## 设计原则

### 1. 简洁高效

- 界面简洁，去除不必要的装饰元素
- 操作路径最短，常用功能一键可达
- 信息层级清晰，重点内容突出
- 减少用户认知负担

### 2. 专业可靠

- 视觉风格专业、稳重，适合服务器管理场景
- 数据展示准确、实时、可信
- 操作有明确反馈，危险操作有二次确认
- 错误状态有清晰提示和解决方案

### 3. 一致统一

- 全局使用统一的设计语言和组件
- 相同功能在不同模块中表现一致
- 配色、间距、字体、图标遵循统一规范
- 交互模式统一，降低学习成本

### 4. 响应式适配

- 适配不同屏幕尺寸（桌面端为主，兼顾平板）
- 侧边栏可折叠，内容区自适应
- 表格在小屏幕下可横向滚动
- 弹窗和抽屉适配视口大小

### 侧边栏

- **宽度**：展开 240px，折叠 64px
- **背景**：`--color-card`（白色），右侧边框 `--color-border`
- **菜单项**：高度 40px，左右内边距 16px，图标 18px
- **选中态**：背景 `--color-primary` 10% 透明度，文字 `--color-primary`，左侧 3px 主色条
- **悬停态**：背景 `rgba(0,0,0,0.04)`
- **分组**：模块间用 8px 间距分隔，分组标题 12px 灰色文字

### 顶栏

- **高度**：56px
- **背景**：`--color-card`（白色），底部边框
- **左侧**：Logo（24px）+ 产品名称（16px Medium）
- **中间**：面包屑导航（14px，分隔符 `/`）
- **右侧**：搜索、通知铃铛、用户头像+名称、下拉菜单

### 内容区

- **内边距**：24px
- **页面标题**：20px Medium，底部间距 16px
- **页面描述**：14px text-2，底部间距 20px
- **卡片间距**：16px（同排）、20px（上下排）

### 栅格系统

使用 24 栏栅格（Naive UI 内置）：

| 断点 | 宽度 | 用途 |
|------|------|------|
| xs | < 768px | 手机（适配，非主要目标） |
| sm | ≥ 768px | 平板竖屏 |
| md | ≥ 992px | 平板横屏 / 小屏笔记本 |

## 组件规范

### 按钮

| 类型 | 样式 | 用途 |
|------|------|------|
| 主按钮 (Primary) | 主色背景，白色文字 | 主要操作、表单提交 |
| 次按钮 (Default) | 白色背景，灰色边框 | 次要操作、取消 |
| 虚线按钮 (Dashed) | 白色背景，虚线边框 | 添加、新建 |
| 文字按钮 (Text) | 透明背景，主色文字 | 表格行内操作、链接 |
| 危险按钮 (Error) | 红色背景，白色文字 | 删除、危险操作 |

#### 按钮尺寸

| 尺寸 | 高度 | 内边距 | 字号 | 用途 |
|------|------|--------|------|------|
| small | 28px | 0 10px | 12px | 表格行内、紧凑空间 |
| medium | 34px | 0 14px | 14px | 标准按钮（默认） |
| large | 40px | 0 18px | 14px | 弹窗底部、重要操作 |

#### 按钮规范

- 同一操作区域最多 1 个主按钮
- 危险操作使用危险按钮，并需二次确认
- 按钮文字使用动词，不超过 4 个汉字
- 加载中状态显示 loading 图标，禁用点击
- 禁用状态透明度 50%，不可点击

### 表格

- **表头**：背景 `rgba(0,0,0,0.02)`，文字 12px text-2，高度 44px
- **行高**：48px（标准），40px（紧凑）
- **行悬停**：背景 `rgba(0,0,0,0.02)`
- **斑马纹**：可选，偶数行背景 `rgba(0,0,0,0.015)`
- **边框**：底部边框 `--color-border`
- **空状态**：居中显示图标 + "暂无数据"文字
- **加载中**：骨架屏或 loading 遮罩

#### 表格列规范

| 列类型 | 宽度 | 对齐 | 说明 |
|--------|------|------|------|
| ID/序号 | 60-80px | 居中 | 固定宽度 |
| 名称/标题 | 自适应 | 左对齐 | 主要信息列 |
| 状态 | 100px | 居中 | 标签展示 |
| 时间 | 160-180px | 左对齐 | 固定宽度 |
| 操作 | 120-200px | 居中 | 文字按钮组 |

### 表单

- **标签**：14px，右对齐，宽度 100px，间距 12px
- **输入框**：高度 34px，圆角 4px，边框 `--color-border`
- **输入框聚焦**：边框主色，外发光 `0 0 0 2px rgba(24,160,88,0.2)`
- **必填标记**：标签前红色 `*`
- **错误提示**：输入框下方 12px 红色文字
- **帮助文字**：输入框下方 12px text-3 灰色文字
- **表单项间距**：垂直 20px
- **表单宽度**：最大 600px，超出用多列布局

### 标签 (Tag)

| 类型 | 颜色 | 用途 |
|------|------|------|
| success | 绿色 | 运行中、成功、已启用 |
| warning | 橙色 | 待处理、执行中 |
| error | 红色 | 异常、失败、已停止 |
| info | 蓝色 | 信息、未配置 |
| default | 灰色 | 中性状态、分类 |

- 标签高度 22px，内边距 0 8px，字号 12px，圆角 4px
- 状态标签使用圆点 + 文字形式

### 卡片

- **背景**：白色，圆角 6px，阴影 `--shadow-sm`
- **内边距**：16-24px
- **卡片标题**：16px Medium，底部 12px 间距
- **卡片头部**：可包含标题、描述、操作按钮
- **卡片悬浮**：阴影变为 `--shadow-md`（可选交互）

### 弹窗 (Modal)

- **宽度**：小 480px，中 600px，大 800px
- **标题栏**：高度 56px，18px Medium 标题，右侧关闭按钮
- **内容区**：内边距 24px，最大高度 60vh，超出滚动
- **底部操作栏**：高度 64px，右对齐按钮组，按钮间距 12px
- **遮罩**：`rgba(0,0,0,0.5)`
- **关闭方式**：右上角 X、遮罩点击、ESC 键、取消按钮

### 抽屉 (Drawer)

- **宽度**：360px（窄）、520px（标准）、720px（宽）
- **从右侧滑入**，动画 250ms
- **标题栏**和底部操作栏同弹窗规范
- 适用于详情查看、快速编辑、设置面板

### 消息提示

| 类型 | 组件 | 用途 | 位置 |
|------|------|------|------|
| 全局消息 | Message | 操作成功/失败提示 | 顶部居中，3秒自动消失 |
| 通知 | Notification | 告警、系统通知 | 右上角，可手动关闭 |
| 对话框 | Dialog | 危险操作确认 | 居中模态 |

## 图标规范

- **双体系决策表（审计 D05）**：项目并存两套图标，边界如下，新图标必须归入其一，不得再造第三套。

| 体系 | 位置 | 规格 | 适用范围 |
|------|------|------|----------|
| 专属集 `PanelIcons.ts` | `frontend/src/components/PanelIcons.ts` | stroke 1.7、圆头、currentColor、aria-hidden，10 个器物图标 | **仅侧栏一级导航入口**（机架/地球/数据库/立方体/终端/仪表盘/磁带/防火墙/证书/计划任务）——产品的「门面」图形，需与通用图标有辨识度差 |
| 通用集 `@vicons/ionicons5` | npm 依赖 | Ionicons 5 官方描边风格 | 页内一切操作/状态/装饰图标（按钮、Tab、空态、下拉、面包屑）；默认 `Outline` 风格，不混用 Fill |

- **新增图标的判断顺序**：是侧栏一级入口吗？是 → 在 PanelIcons.ts 按同规格手绘；否 → 在 ionicons5 里挑，挑不到再考虑扩展专属集（需过设计评审）。
- **图标尺寸档（收敛为 3 档声明值）**：

| 档 | 尺寸 | 场景 |
|----|------|------|
| sm | 16px | 按钮内图标、行内装饰 |
| md | 20px | 卡片标题、下拉菜单项 |
| lg | 34px | 侧栏 Logo 标记、空态大图（空态如需更大按 2×md 取整） |

- **图标颜色**：继承文字颜色，状态图标使用对应功能色
- **图标与文字间距**：8px（`--space-2`）

## 暗色模式（规划中）

暗色模式设计规范将在后续版本中补充，主要原则：

- 背景色：`#1a1a1a`（页面）、`#242424`（卡片）
- 文字色：反色处理，主要文字 `rgba(255,255,255,0.9)`
- 主色保持不变，调整亮度以适配暗色背景
- 通过 CSS 变量切换，无需修改组件代码
- 跟随系统设置或用户手动切换

## 无障碍设计

- 所有交互元素可通过键盘操作（Tab 导航、Enter 确认、ESC 关闭）
- 焦点状态有明显的视觉指示（外发光）
- 图标按钮有 `aria-label` 属性
- 颜色不是唯一的信息传达方式（状态同时用文字和颜色）
- 文字对比度符合 WCAG AA 标准（4.5:1）
- 表单错误有明确的文字提示，不仅是红色边框
- 动画支持 `prefers-reduced-motion` 媒体查询

## 决策记录

### DR-001 · NCard 网格豁免边界（审计 D06②）

弹窗/卡片统一归口 PageCard、ContentModal、ModalForm 三个原子组件，但以下场景**豁免**直用 NCard：

| 位置 | 用法 | 豁免理由 |
|------|------|----------|
| `appstore/AppStoreTab.vue` | `NCard hoverable` 应用卡片网格 | 商品卡语义：需 hover 抬升、封面区+操作区复合结构，PageCard 是页面容器不是商品卡 |
| `plugins/index.vue` | `NCard hoverable` 插件卡片网格 | 同上 |
| `nodes/index.vue` | `NCard size="small"` 节点卡片网格 | 多实例并列的实体卡，非页面分区 |
| `login/Login.vue` / `ChangePassword.vue` / `ResetPassword.vue` | 居中表单卡 | 登录态外的独立页，不在 DefaultLayout 的 PageCard 体系内 |

边界口诀：**页面分区 → PageCard；重复实体卡 / 商品卡 → NCard；一切弹窗 → ContentModal/ModalForm**。新增页面先问归属，拿不准默认 PageCard。

### DR-002 · 性能预算（审计 D16）

| 指标 | 预算 | 现状基线（2026-10-21 vite build 实测 gzip） | 超预算处理 |
|------|------|----------------------------------|------------|
| 首屏必载 JS（index + naive-ui，gzip） | < 500 KB | 96 + 380 = **476 KB**（贴线） | naive-ui 已按需 tree-shake 至此；进一步压需换轻量组件方案或自研核心组件，属架构级决策 |
| 异步路由 chunk（gzip，懒加载不阻塞首屏） | < 200 KB | echarts 168 / xterm 72 / monaco 580（编辑器页专用，进入 CodeEditor 路由才加载） | monaco 超预算属已知豁免：仅容器终端/代码编辑场景触达；若需压缩可切 `monaco-editor/core` 更薄内核或 lazy 语言包 |
| CSS（gzip） | < 60 KB | ~1 KB/页 + 全局 | — |

> 注：构建时 1500 KB raw 警告来自 monaco（2244 KB raw / 580 KB gzip）——异步分包不进首屏，警告可忽略；若要消除告警可调 `chunkSizeWarningLimit` 或接受现状。

- 构建门：`npm run build` 输出各 chunk 体积；单 chunk 超预算时在 CI 评论中提示（暂无人工看护时以本表为准）。

### DR-003 · Token 明文存 localStorage 的风险决策（审计 D26②）

现状：`stores/auth.ts` 将 JWT 存 `localStorage`（`cloudpivot_token`），XSS 窃取面存在。

**决策：维持 localStorage，不用 HttpOnly cookie。** 理由：

1. **威胁模型**：面板定位内网/自托管场景（docker-compose 单机部署），攻击者需先拿到同源 JS 执行权——而 CSP 已禁 `unsafe-inline`/脚本白名单化（见安全响应头配置），v-html 0 处，XSS 注入面在审计中为干净项。
2. **架构权衡**：HttpOnly cookie 方案需后端配合 SameSite/CSRF token 全链路改造；当前前后端分离、API 首次用 token 交换，改 cookie 的收益低于改造成本。
3. **残余风险**：若未来暴露公网，必须重新评估——届时优先引入 httpOnly + refresh token 轮换，而非仅移动存储位置。

**复审触发条件**：产品公网化、引入第三方脚本（统计/客服）、或 XSS 注入面出现实锤漏洞时，本决策强制重开。

### DR-004 · CSP `unsafe-eval` 移除（审计 D26③）

**取证结论（2026-10-21，dist/assets grep）**：主包 `index-*.js` 中存在 1 处 `new Function`，来源为 **vue-i18n 的 JIT 消息编译**（`__INTLIFY_JIT_COMPILATION__` 宏分支，运行时把 locale message 编译为函数）。Vite/vue 本体不需要 eval，但 i18n 需要。

**决策：保留 `unsafe-eval`。** 移除路径（若未来要收紧 CSP）：引入 `@intlify/unplugin-vue-i18n` 在构建期预编译 locale 消息，产物不再含 JIT 分支，届时可同步删 CSP 中的 `unsafe-eval`。当前内网部署场景下，收益不抵改造成本。
