# SSH 安全

SSH 安全模块提供 SSH 服务配置管理、SSH 密钥管理、登录日志查看和 Fail2ban 防护功能，帮助您加固服务器 SSH 访问安全，防止暴力破解和未授权访问。

## 功能概览

- SSH 配置查看与修改
- SSH 公钥管理（添加/删除/查看）
- SSH 登录日志查看
- Fail2ban 状态查看
- Fail2ban 配置修改
- IP 手动封禁/解封

## SSH 配置管理

### 查看当前配置

进入"SSH 安全"页面，顶部展示当前 SSH 配置：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 端口 | SSH 服务监听端口 | 22 |
| 允许密码登录 | 是否允许使用密码认证 | yes |
| 允许 root 登录 | 是否允许 root 直接登录 | yes |
| 公钥认证 | 是否启用公钥认证 | yes |
| 最大认证尝试次数 | 单次连接最大密码尝试次数 | 6 |
| 登录超时时间 | 认证超时时间（秒） | 120 |
| X11 转发 | 是否允许 X11 图形转发 | no |
| TCP 转发 | 是否允许 TCP 端口转发 | yes |

### 修改配置

1. 在配置表单中修改需要调整的项
2. 点击"保存配置"
3. 系统验证配置有效性
4. 验证通过后写入 `sshd_config` 并重启 SSH 服务

> **警告**：修改 SSH 端口或禁用密码登录前，请确保：
> 1. 已添加 SSH 公钥并测试密钥登录正常
> 2. 新端口已在防火墙中开放
> 3. 有备用访问方式（如云控制台 VNC）
> 错误配置可能导致无法通过 SSH 连接服务器。

### 安全配置建议

| 配置项 | 推荐值 | 原因 |
|--------|--------|------|
| 端口 | 非 22（如 2222） | 减少自动化扫描和暴力破解 |
| 允许密码登录 | no | 防止密码暴力破解，使用密钥登录 |
| 允许 root 登录 | no | 禁止 root 直接登录，使用普通用户 + sudo |
| 最大认证尝试次数 | 3 | 限制密码尝试次数 |
| 登录超时 | 60 | 减少未认证连接占用时间 |

## SSH 密钥管理

### 查看已添加的公钥

在"SSH 密钥"区域展示 `~/.ssh/authorized_keys` 中的所有公钥：

| 列 | 说明 |
|----|------|
| 指纹 | 公钥的 MD5/SHA256 指纹 |
| 类型 | ssh-rsa / ssh-ed25519 / ecdsa-sha2-nistp256 等 |
| 注释 | 公钥中的注释信息（通常是邮箱或主机名） |
| 添加时间 | 公钥添加到服务器的时间 |
| 操作 | 删除 |

### 添加公钥

1. 在本地生成 SSH 密钥对（如尚未生成）：
   ```bash
   ssh-keygen -t ed25519 -C "your_email@example.com"
   ```
2. 复制公钥内容（`~/.ssh/id_ed25519.pub`）
3. 在面板"添加公钥"文本框中粘贴公钥内容
4. 点击"添加"
5. 系统验证公钥格式后写入 `authorized_keys`
6. 测试使用密钥登录：`ssh -i ~/.ssh/id_ed25519 user@server`

### 删除公钥

1. 在密钥列表中找到要删除的公钥
2. 点击"删除"按钮
3. 确认删除
4. 该公钥将无法再用于登录

> 删除前请确认还有其他可用的登录方式，避免被锁在服务器外。

## 登录日志

在"登录日志"区域展示最近的 SSH 登录记录：

| 列 | 说明 |
|----|------|
| 时间 | 登录时间 |
| 用户名 | 登录使用的用户名 |
| IP 地址 | 来源 IP |
| 端口 | 来源端口 |
| 状态 | 成功 / 失败 |
| 认证方式 | password / publickey |

日志支持分页浏览（默认每页 20 条），可用于：

- 发现异常登录（陌生 IP、非工作时间登录）
- 统计登录失败次数（暴力破解迹象）
- 审计用户登录行为

## Fail2ban 防护

Fail2ban 是一款入侵防护软件，通过监控日志自动封禁频繁登录失败的 IP。

### 状态查看

展示 Fail2ban 运行状态：

| 项目 | 说明 |
|------|------|
| 服务状态 | running / stopped |
| 监控服务 | sshd |
| 当前封禁数 | 当前被封禁的 IP 数量 |
| 总封禁次数 | 历史累计封禁次数 |
| 封禁列表 | 当前被封禁的 IP 及封禁时间 |

### 配置修改

可调整以下 Fail2ban 参数：

| 参数 | 说明 | 推荐值 | 范围 |
|------|------|--------|------|
| maxretry | 最大重试次数，超过即封禁 | 5 | 1-20 |
| findtime | 检测时间窗口（秒） | 600 | 60-86400 |
| bantime | 封禁时长（秒） | 3600 | 60-31536000 |

配置说明：在 `findtime` 时间窗口内，同一 IP 失败 `maxretry` 次后，将被封禁 `bantime` 秒。

例如：`maxretry=5, findtime=600, bantime=3600` 表示 10 分钟内失败 5 次则封禁 1 小时。

### 手动封禁 IP

1. 在"手动操作"区域输入要封禁的 IP
2. 点击"封禁"
3. 该 IP 立即被加入封禁列表
4. 适用于已确认的恶意 IP

### 手动解封 IP

1. 在封禁列表中找到要解封的 IP
2. 点击"解封"按钮
3. 或在"手动操作"中输入 IP 后点击"解封"
4. 该 IP 立即恢复访问

适用于误封的 IP（如自己多次输错密码被封）。

## 常见使用场景

### 场景一：SSH 安全加固

1. 先在本地生成 SSH 密钥并添加到面板
2. 测试密钥登录正常后，禁用密码登录
3. 修改 SSH 端口为非标准端口（如 2222）
4. 在防火墙中开放新端口，关闭旧 22 端口
5. 禁用 root 登录，使用普通用户 + sudo
6. 启用并配置 Fail2ban
7. 定期查看登录日志，确认无异常

### 场景二：发现暴力破解

1. 查看登录日志，发现大量来自同一 IP 的失败登录
2. 查看 Fail2ban 状态，确认该 IP 是否已被自动封禁
3. 如未被封，手动封禁该 IP
4. 调整 Fail2ban 配置（降低 maxretry、延长 bantime）
5. 检查是否有其他 IP 也在攻击
6. 考虑修改 SSH 端口减少扫描

### 场景三：团队成员密钥管理

1. 为每位团队成员生成独立的 SSH 密钥对
2. 将成员公钥添加到面板
3. 在密钥列表中可查看所有成员的密钥（通过注释识别）
4. 成员离职时，删除对应的公钥
5. 定期审计密钥列表，清理不再使用的密钥
6. 禁用密码登录，强制所有成员使用密钥登录
