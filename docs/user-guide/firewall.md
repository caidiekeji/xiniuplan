# 防火墙

防火墙模块提供服务器端口规则的可视化管理，支持添加、删除、启用/禁用防火墙规则，并提供安全建议功能，帮助您加固服务器网络安全。

## 功能概览

- 防火墙规则列表（分页、按类型筛选）
- 添加防火墙规则（端口/协议/方向）
- 删除规则
- 启用/禁用规则
- 安全建议检查

## 前置条件

防火墙功能依赖系统防火墙服务（iptables / firewalld / ufw）。使用前请确认：

1. 系统已安装并启用防火墙服务
2. 运行云枢面板的用户具有防火墙管理权限（通常需要 root）
3. 已开放面板自身端口（默认 8888），避免误操作导致无法访问面板

> **警告**：错误的防火墙规则可能导致您无法远程连接服务器。操作前请确保有其他访问方式（如云厂商控制台 VNC），并切勿封禁 SSH 端口和面板端口。

## 规则列表

进入"防火墙"页面，展示所有防火墙规则：

| 列 | 说明 |
|----|------|
| ID | 规则唯一标识 |
| 类型 | 入站（inbound）/ 出站（outbound） |
| 协议 | TCP / UDP / ICMP / ALL |
| 端口 | 端口号或端口范围（如 80, 443, 3000-4000） |
| 源地址 | 允许的源 IP（空表示任意） |
| 动作 | accept（允许）/ drop（丢弃）/ reject（拒绝） |
| 状态 | 启用 / 禁用 |
| 描述 | 规则备注 |
| 操作 | 切换状态/删除 |

### 筛选

- 按规则类型筛选（入站/出站）
- 按协议筛选
- 支持分页浏览

## 添加规则

### 操作步骤

1. 点击"添加规则"按钮
2. 填写规则配置：

| 字段 | 说明 | 示例 |
|------|------|------|
| 类型 | 入站或出站 | inbound |
| 协议 | TCP / UDP / ICMP / ALL | TCP |
| 端口 | 端口号或范围 | 443 |
| 源地址 | 允许的源 IP/CIDR（留空表示任意） | 192.168.1.0/24 |
| 动作 | accept / drop / reject | accept |
| 描述 | 规则说明 | HTTPS 访问 |

3. 点击"添加"，规则立即生效

### 常用规则示例

| 用途 | 类型 | 协议 | 端口 | 动作 |
|------|------|------|------|------|
| HTTP 访问 | 入站 | TCP | 80 | accept |
| HTTPS 访问 | 入站 | TCP | 443 | accept |
| SSH 访问 | 入站 | TCP | 22 | accept |
| 面板访问 | 入站 | TCP | 8888 | accept |
| MySQL（仅内网） | 入站 | TCP | 3306 | accept（源地址限内网） |
| 禁止某 IP | 入站 | ALL | 所有 | drop（源地址指定） |

## 规则操作

### 启用/禁用规则

1. 在规则列表中找到目标规则
2. 点击状态切换按钮
3. 禁用的规则不会生效，但保留配置
4. 再次点击可重新启用

### 删除规则

1. 点击规则的"删除"按钮
2. 确认删除
3. 规则立即从防火墙中移除

> 删除规则前请确认不会影响正常服务。例如删除 SSH 规则可能导致无法远程连接。

## 安全建议

点击"安全建议"按钮，系统将自动检查服务器安全配置并给出建议：

### 检查项

| 检查项 | 说明 | 建议 |
|--------|------|------|
| SSH 端口 | 是否使用默认 22 端口 | 建议修改为非标准端口 |
| 密码登录 | 是否允许 SSH 密码登录 | 建议禁用密码登录，使用密钥 |
| root 登录 | 是否允许 root 直接登录 | 建议禁用 root 登录 |
| 开放端口 | 是否有不必要的端口开放 | 关闭不需要的端口 |
| 防火墙状态 | 防火墙是否启用 | 确保防火墙已启用 |
| 面板端口 | 面板端口是否对外开放 | 建议限制访问 IP |

### 使用建议

1. 定期运行安全建议检查
2. 根据建议逐项加固
3. 修改 SSH 配置前确保有备用访问方式
4. 加固后测试所有关键服务是否正常
5. 记录所有安全配置变更

## 常见使用场景

### 场景一：开放网站端口

新部署网站后需要开放 HTTP 和 HTTPS 端口：

1. 进入防火墙页面
2. 添加规则：入站 TCP 80，动作 accept，描述"HTTP"
3. 添加规则：入站 TCP 443，动作 accept，描述"HTTPS"
4. 确认规则已启用
5. 在浏览器中测试网站访问

### 场景二：限制数据库端口访问

数据库端口不应暴露到公网，仅允许内网或特定 IP 访问：

1. 添加规则：入站 TCP 3306，源地址 `10.0.0.0/8`，动作 accept
2. 确保没有其他规则允许任意 IP 访问 3306
3. 如有旧的开放规则，删除或禁用它
4. 从外部测试 3306 端口是否无法连接
5. 从内网服务器测试是否可正常连接

### 场景三：封禁恶意 IP

发现某 IP 持续攻击或扫描时：

1. 添加规则：入站 ALL，源地址 `<恶意IP>`，动作 drop
2. 规则立即生效，该 IP 的所有连接将被丢弃
3. 可在 SSH 登录日志中确认攻击是否停止
4. 结合 Fail2ban 可实现自动封禁

### 场景四：安全加固检查

1. 点击"安全建议"运行检查
2. 查看检查结果和建议
3. 按优先级逐项处理（先处理高危项）
4. 修改 SSH 配置前在 SSH 安全页面操作
5. 全部完成后再次运行检查确认
6. 定期（如每月）重复检查
