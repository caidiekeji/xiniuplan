# 用户与权限

用户与权限模块提供基于 RBAC（基于角色的访问控制）的用户管理系统，支持用户创建与管理、角色定义与权限分配、TOTP 二次验证，帮助您精细控制面板的访问权限。

## 功能概览

- 用户管理（创建/编辑/删除/启用禁用/修改密码）
- 角色管理（内置角色 + 自定义角色）
- 权限树（15 个模块、50+ 权限点）
- RBAC 权限控制
- TOTP 二次验证（Google Authenticator 等）
- 用户登录审计

## RBAC 模型

云枢面板采用标准的 RBAC 权限模型：

```
用户(User) → 属于 → 角色(Role) → 拥有 → 权限(Permission)
```

- **用户**：登录面板的账号
- **角色**：一组权限的集合，用户通过角色获得权限
- **权限**：具体的操作许可，格式为 `模块:动作`（如 `site:create`）

一个用户只能属于一个角色，角色可包含多个权限。

## 内置角色

系统预置三个内置角色，不可删除和修改：

| 角色 | Code | 权限说明 |
|------|------|----------|
| 超级管理员 | `super_admin` | 拥有全部权限（`*`） |
| 管理员 | `admin` | 除用户删除和系统设置更新外的全部权限 |
| 普通用户 | `user` | 仅拥有查看类权限（所有 `*:view`） |

> 内置角色标记为 `is_system=true`，不可修改或删除。

## 权限体系

### 权限模块

系统包含 15 个功能模块，每个模块有对应的查看和操作权限：

| 模块 | 权限码前缀 | 权限说明 |
|------|-----------|----------|
| 网站管理 | `site:` | view / create / update / delete |
| 数据库管理 | `database:` | view / create / update / delete |
| 文件管理 | `file:` | view / create / update / delete |
| Web 终端 | `terminal:` | view / create |
| 容器管理 | `container:` | view / create / update / delete |
| 应用商店 | `appstore:` | view / install |
| 防火墙 | `firewall:` | view / update |
| 备份恢复 | `backup:` | view / create / delete |
| 监控 | `monitor:` | view |
| 用户管理 | `user:` | view / create / update / delete |
| 审计日志 | `audit:` | view |
| 系统设置 | `setting:` | view / update |
| 告警管理 | `alert:` | view / create / update / delete |
| 计划任务 | `cron:` | view / create / update / delete |

### 权限码格式

权限码格式为 `模块:动作`，例如：

- `site:view` — 查看网站列表
- `site:create` — 创建网站
- `site:update` — 编辑网站
- `site:delete` — 删除网站
- `*` — 全部权限（仅超级管理员）

### 权限树

系统提供完整的权限树结构，按模块分组展示所有权限点，用于角色编辑时的权限选择。权限树包含：

- 模块标识（如 `site`）
- 模块显示名称（如"网站管理"）
- 权限项列表（权限码 + 中文标签）

## 用户管理

### 用户列表

进入"用户管理"页面，展示所有用户：

| 列 | 说明 |
|----|------|
| ID | 用户唯一标识 |
| 用户名 | 登录用户名 |
| 角色 | 所属角色名称 |
| 状态 | active（正常）/ disabled（已禁用） |
| TOTP | 是否已启用二次验证 |
| 最后登录 | 最后一次登录时间 |
| 创建时间 | 账号创建时间 |
| 操作 | 编辑/修改密码/禁用/启用/删除 |

### 创建用户

1. 点击"创建用户"按钮
2. 填写用户信息：

| 字段 | 说明 |
|------|------|
| 用户名 | 登录用户名，唯一，3-32 字符 |
| 密码 | 初始密码，至少 8 位 |
| 角色 | 选择所属角色 |
| 状态 | active / disabled |

3. 点击"创建"
4. 将账号信息告知用户，建议首次登录后修改密码

### 编辑用户

1. 点击用户的"编辑"按钮
2. 可修改：角色、状态
3. 用户名不可修改
4. 保存后立即生效

### 修改密码

- **修改自己的密码**：需要输入旧密码验证，再输入新密码
- **管理员修改他人密码**：无需旧密码，直接设置新密码

密码要求：至少 8 位，建议包含大小写字母、数字和特殊字符。

### 启用/禁用用户

- **禁用**：用户无法登录，已登录的会话将失效
- **启用**：恢复用户登录权限

### 删除用户

1. 点击"删除"按钮
2. 确认删除
3. 用户及其登录记录将被删除

> 不能删除当前登录的用户自己。超级管理员账号建议保留。

## 角色管理

### 角色列表

在"角色管理"标签页展示所有角色：

| 列 | 说明 |
|----|------|
| ID | 角色唯一标识 |
| 名称 | 角色显示名称 |
| Code | 角色唯一标识码 |
| 描述 | 角色说明 |
| 权限数 | 包含的权限数量 |
| 系统角色 | 是否为内置角色 |
| 创建时间 | 角色创建时间 |
| 操作 | 编辑/删除 |

### 创建角色

1. 点击"创建角色"按钮
2. 填写角色信息：

| 字段 | 说明 |
|------|------|
| 角色名称 | 显示名称，如"运维工程师" |
| 角色 Code | 唯一标识，如 `ops`，仅字母数字下划线 |
| 描述 | 角色说明 |
| 权限 | 在权限树中勾选该角色拥有的权限 |

3. 点击"创建"

### 编辑角色

1. 点击角色的"编辑"按钮
2. 可修改：名称、描述、权限
3. Code 不可修改
4. 内置角色不可编辑
5. 保存后，属于该角色的所有用户权限立即更新

### 删除角色

1. 点击"删除"按钮
2. 确认删除
3. 内置角色不可删除
4. 角色下仍有用户时不可删除（需先将用户移到其他角色）

## TOTP 二次验证

TOTP（基于时间的一次性密码）为账号提供额外的安全保护，启用后登录时除了密码还需要输入动态验证码。

### 启用 TOTP

1. 进入个人设置或用户管理
2. 点击"启用 TOTP"
3. 系统生成二维码和密钥
4. 使用 Google Authenticator、Microsoft Authenticator 等 App 扫描二维码
5. 输入 App 中显示的 6 位验证码进行验证
6. 验证成功后 TOTP 启用
7. 系统显示恢复码（Recovery Codes），请妥善保存

> 恢复码用于手机丢失时紧急登录，每个恢复码只能使用一次。请下载或复制保存到安全位置。

### 登录流程（启用 TOTP 后）

1. 输入用户名和密码
2. 验证通过后，系统返回 `require_totp: true` 和临时令牌
3. 用户输入 TOTP 验证码
4. 验证通过后签发正式的访问令牌
5. 如验证码连续错误多次，账号将被临时锁定

### 禁用 TOTP

1. 在个人设置中点击"禁用 TOTP"
2. 输入当前密码验证
3. TOTP 禁用，恢复密码-only 登录

管理员可强制为用户禁用 TOTP（如用户手机丢失且恢复码也丢失时）。

## 常见使用场景

### 场景一：创建运维角色

1. 创建角色，名称"运维工程师"，Code `ops`
2. 勾选权限：网站全部、数据库全部、文件全部、容器全部、防火墙全部、备份全部、计划任务全部
3. 不勾选：用户管理、系统设置
4. 创建用户，分配到运维角色
5. 运维人员可管理服务器但不能修改面板设置和用户

### 场景二：创建只读审计角色

1. 创建角色，名称"审计员"，Code `auditor`
2. 仅勾选所有模块的 `view` 权限
3. 特别勾选 `audit:view`（审计日志查看）
4. 创建审计用户分配到此角色
5. 审计员可查看所有数据和日志，但不能执行任何修改操作

### 场景三：强制启用 TOTP

1. 在系统设置中配置安全策略（如要求所有管理员启用 TOTP）
2. 管理员账号启用 TOTP 并保存恢复码
3. 为其他用户创建账号时告知启用 TOTP
4. 定期检查用户列表，确认关键账号都已启用 TOTP
5. 结合 SSH 密钥登录，实现全方位安全防护
