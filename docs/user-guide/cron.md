# 计划任务

计划任务模块提供可视化的定时任务管理能力，支持 Shell 命令、备份、URL 请求和应用重启四种任务类型，可设置 Cron 表达式精确控制执行时间，并提供执行日志查看和手动触发功能。

## 功能概览

- 多类型定时任务（Shell / 备份 / URL / 应用重启）
- Cron 表达式调度
- 任务启用/禁用
- 手动触发执行
- 执行日志查看
- 下次执行时间预测

## 任务类型

| 类型 | 标识 | 说明 |
|------|------|------|
| Shell 命令 | `shell` | 执行指定的 Shell 命令或脚本 |
| 备份任务 | `backup` | 执行指定类型的备份操作 |
| URL 请求 | `url` | 向指定 URL 发送 HTTP 请求 |
| 应用重启 | `app_restart` | 重启指定的已安装应用 |

## 创建计划任务

### 操作步骤

1. 进入"计划任务"页面，点击"创建任务"
2. 填写任务基本信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 任务名称 | 任务的描述性名称 | 每日数据库备份 |
| 任务类型 | shell / backup / url / app_restart | backup |
| Cron 表达式 | 执行时间调度表达式 | `0 3 * * *`（每天凌晨3点） |
| 命令/目标 | 根据类型填写具体内容 | 见下方说明 |
| 备注 | 可选的任务描述 | 每天凌晨3点备份MySQL |

3. 点击"创建"，任务默认启用
4. 系统将按 Cron 表达式自动执行

### 各类型任务参数

#### Shell 命令（shell）

- **命令**：要执行的 Shell 命令，支持多条命令（用 `;` 或 `&&` 连接）
- 示例：`cd /www/wwwroot && rm -rf *.log`
- 示例：`/usr/bin/php /path/to/script.php`

#### 备份任务（backup）

- **目标**：备份类型和目标，格式为 `类型:目标`
- 示例：`database:mysql_instance_1:mydb`
- 示例：`site:example.com`

#### URL 请求（url）

- **目标**：要请求的 URL 地址
- 示例：`https://example.com/cron.php`
- 系统发送 GET 请求，适用于触发 Web 应用的定时任务

#### 应用重启（app_restart）

- **目标**：要重启的应用 key
- 示例：`nextcloud`
- 系统将重启指定应用的 Docker 容器

### Cron 表达式

Cron 表达式格式为 `分 时 日 月 周`，共 5 个字段：

| 字段 | 取值范围 | 特殊字符 |
|------|----------|----------|
| 分 | 0-59 | `*` `,` `-` `/` |
| 时 | 0-23 | `*` `,` `-` `/` |
| 日 | 1-31 | `*` `,` `-` `/` `?` |
| 月 | 1-12 | `*` `,` `-` `/` |
| 周 | 0-7（0和7均为周日） | `*` `,` `-` `/` |

常用示例：

| 表达式 | 说明 |
|--------|------|
| `* * * * *` | 每分钟执行 |
| `0 * * * *` | 每小时整点执行 |
| `0 3 * * *` | 每天凌晨 3 点执行 |
| `0 3 * * 0` | 每周日凌晨 3 点执行 |
| `0 0 1 * *` | 每月 1 号凌晨执行 |
| `*/5 * * * *` | 每 5 分钟执行 |
| `0 9-18 * * 1-5` | 工作日 9 点到 18 点每小时执行 |

## 任务列表

任务列表展示所有计划任务：

| 列 | 说明 |
|----|------|
| ID | 任务唯一标识 |
| 名称 | 任务名称 |
| 类型 | shell / backup / url / app_restart |
| 调度 | Cron 表达式 |
| 状态 | enabled（已启用）/ disabled（已禁用） |
| 上次执行 | 最后一次执行时间 |
| 下次执行 | 预测的下次执行时间 |
| 操作 | 编辑/启用/禁用/触发/日志/删除 |

## 任务操作

### 启用/禁用

- **禁用** — 暂停任务调度，任务不会自动执行，但保留配置
- **启用** — 恢复任务调度，按 Cron 表达式继续执行

### 手动触发

1. 点击"触发"按钮
2. 系统立即执行一次该任务（不等待调度时间）
3. 适用于测试任务是否正常工作
4. 触发后可在执行日志中查看结果

### 编辑任务

1. 点击"编辑"按钮
2. 修改任务配置（名称、类型、Cron、命令等）
3. 保存后新配置立即生效

### 删除任务

1. 点击"删除"按钮
2. 确认删除
3. 任务及其执行日志将被删除

## 执行日志

点击任务的"日志"按钮，查看该任务的历史执行记录：

| 列 | 说明 |
|----|------|
| ID | 日志记录 ID |
| 任务名称 | 所属任务名称 |
| 开始时间 | 执行开始时间 |
| 结束时间 | 执行结束时间 |
| 执行结果 | success（成功）/ failed（失败）/ running（执行中） |
| 输出 | 命令输出内容或错误信息 |

### 日志详情

点击日志记录可查看完整输出内容：

- Shell 命令的 stdout 和 stderr
- 备份任务的执行结果和文件信息
- URL 请求的响应状态码
- 应用重启的结果

日志默认按时间倒序排列，支持分页浏览（默认每页 20 条）。

## 常见使用场景

### 场景一：定期数据库备份

1. 创建任务，类型选择 `backup`
2. Cron 设置为 `0 3 * * *`（每天凌晨 3 点）
3. 目标设置为 `database:<实例ID>:<数据库名>`
4. 启用任务
5. 每天凌晨自动备份，可在日志中确认备份结果
6. 配合另一个清理任务定期删除旧备份

### 场景二：定时清理日志文件

1. 创建任务，类型选择 `shell`
2. Cron 设置为 `0 4 * * 0`（每周日凌晨 4 点）
3. 命令：`find /www/wwwlogs -name "*.log" -mtime +30 -delete`
4. 启用任务
5. 每周自动清理 30 天前的日志文件

### 场景三：触发 Web 应用定时任务

许多 Web 应用（如 WordPress、Discuz）需要定时触发脚本：

1. 创建任务，类型选择 `url`
2. Cron 设置为 `*/15 * * * *`（每 15 分钟）
3. 目标设置为 `https://example.com/wp-cron.php`
4. 启用任务
5. 替代应用自身的伪 Cron，提高执行可靠性

### 场景四：定期重启应用

某些应用长时间运行后可能内存泄漏，需要定期重启：

1. 创建任务，类型选择 `app_restart`
2. Cron 设置为 `0 5 * * *`（每天凌晨 5 点）
3. 目标设置为应用 key（如 `nextcloud`）
4. 启用任务
5. 每天自动重启应用，释放内存资源
