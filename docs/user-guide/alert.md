# 告警通知

告警通知模块提供服务器资源监控告警能力，支持自定义告警规则（CPU、内存、磁盘、网络等），配置多种通知渠道（邮件、Webhook 等），并记录告警历史，帮助您及时发现和处理服务器异常。

## 功能概览

- 告警规则管理（创建/编辑/删除/启用/禁用/测试）
- 通知渠道管理（邮件/Webhook/测试）
- 告警历史记录
- 告警引擎自动评估与触发

## 告警规则

### 规则列表

进入"告警通知"页面，展示所有告警规则：

| 列 | 说明 |
|----|------|
| ID | 规则唯一标识 |
| 名称 | 规则名称 |
| 指标 | 监控指标（CPU/内存/磁盘/网络等） |
| 条件 | 触发条件（大于/小于/等于阈值） |
| 阈值 | 触发阈值 |
| 持续时间 | 异常持续多久后触发 |
| 状态 | 启用 / 禁用 |
| 通知渠道 | 关联的通知渠道 |
| 操作 | 编辑/启用/禁用/测试/删除 |

### 创建告警规则

1. 点击"创建规则"按钮
2. 填写规则配置：

| 字段 | 说明 | 示例 |
|------|------|------|
| 规则名称 | 描述性名称 | CPU 使用率过高 |
| 监控指标 | cpu / memory / disk / network / load | cpu |
| 条件 | `>` 大于 / `<` 小于 / `>=` / `<=` / `==` | `>` |
| 阈值 | 触发阈值（百分比或数值） | 80 |
| 持续时间 | 异常持续多少秒后触发告警 | 300 |
| 通知渠道 | 选择关联的通知渠道（可多选） | 邮件管理员 |
| 告警级别 | info / warning / critical | warning |
| 描述 | 规则说明 | CPU 使用率持续超过 80% 时告警 |

3. 点击"创建"，规则默认启用
4. 告警引擎将按监控采集周期自动评估规则

### 支持的监控指标

| 指标 | 标识 | 单位 | 说明 |
|------|------|------|------|
| CPU 使用率 | cpu | % | 整体 CPU 使用率 |
| 内存使用率 | memory | % | 内存使用百分比 |
| 磁盘使用率 | disk | % | 根分区使用百分比 |
| 网络入站 | network_in | MB/s | 网络下载速率 |
| 网络出站 | network_out | MB/s | 网络上传速率 |
| 系统负载 | load | - | 1 分钟平均负载 |

### 规则操作

- **启用/禁用** — 禁用后规则不会被评估，保留配置
- **测试规则** — 手动触发一次规则评估，用于测试通知渠道是否正常
- **编辑规则** — 修改规则配置，保存后立即生效
- **删除规则** — 删除规则及其关联的告警历史

## 通知渠道

### 渠道列表

在"通知渠道"标签页展示所有已配置的渠道：

| 列 | 说明 |
|----|------|
| ID | 渠道唯一标识 |
| 名称 | 渠道名称 |
| 类型 | email / webhook |
| 配置摘要 | 邮箱地址或 Webhook URL |
| 状态 | 启用 / 禁用 |
| 操作 | 编辑/测试/删除 |

### 邮件渠道

配置 SMTP 邮件通知：

| 字段 | 说明 | 示例 |
|------|------|------|
| 渠道名称 | 渠道描述名 | 管理员邮件 |
| SMTP 服务器 | 邮件服务器地址 | smtp.example.com |
| SMTP 端口 | 服务器端口 | 465 |
| 用户名 | SMTP 认证用户名 | alert@example.com |
| 密码 | SMTP 认证密码 | （密码） |
| 发件人 | 邮件发件人地址 | alert@example.com |
| 收件人 | 告警接收邮箱（多个用逗号分隔） | admin@example.com |
| 使用 SSL | 是否启用 SSL/TLS | 是 |

> SMTP 服务器配置也可在"系统设置 → SMTP 配置"中统一设置。

### Webhook 渠道

配置 Webhook 通知，适用于接入企业微信、钉钉、飞书、Slack 等即时通讯工具：

| 字段 | 说明 | 示例 |
|------|------|------|
| 渠道名称 | 渠道描述名 | 企业微信告警 |
| Webhook URL | 接收告警的 URL | https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx |
| 请求方法 | POST（默认） | POST |
| 请求头 | 自定义 Header（如认证 Token） | Content-Type: application/json |
| 请求体模板 | JSON 模板，支持变量替换 | 见下方 |

#### Webhook 变量

请求体模板支持以下变量：

| 变量 | 说明 |
|------|------|
| `{rule_name}` | 告警规则名称 |
| `{metric}` | 监控指标 |
| `{value}` | 当前值 |
| `{threshold}` | 阈值 |
| `{level}` | 告警级别 |
| `{time}` | 触发时间 |
| `{message}` | 告警消息 |

示例（企业微信机器人）：
```json
{
  "msgtype": "text",
  "text": {
    "content": "【云枢告警】{rule_name}\n指标: {metric}\n当前值: {value}\n阈值: {threshold}\n时间: {time}"
  }
}
```

### 测试渠道

1. 在渠道列表中点击"测试"按钮
2. 系统发送一条测试告警消息
3. 检查邮箱或 Webhook 接收端是否收到
4. 如未收到，检查配置和网络连接

## 告警历史

在"告警历史"标签页查看所有告警触发记录：

| 列 | 说明 |
|----|------|
| ID | 记录 ID |
| 规则名称 | 触发的告警规则 |
| 告警级别 | info / warning / critical |
| 指标值 | 触发时的指标值 |
| 状态 | 已通知 / 通知失败 / 已恢复 |
| 触发时间 | 告警触发时间 |
| 恢复时间 | 异常恢复时间（如已恢复） |

### 筛选

- 按规则筛选（`rule_id`）
- 按状态筛选（`status`）
- 支持分页（默认每页 20 条）

## 告警引擎工作流程

1. **数据采集** — 监控采集器按配置间隔（默认 60 秒）采集系统指标
2. **规则评估** — 告警引擎对每条启用的规则进行评估
3. **条件判断** — 检查当前指标值是否满足触发条件
4. **持续时间检测** — 异常状态持续超过设定时间后触发
5. **告警通知** — 通过关联的通知渠道发送告警消息
6. **历史记录** — 记录告警触发事件
7. **恢复检测** — 指标恢复正常后记录恢复时间

## 常见使用场景

### 场景一：CPU 使用率告警

1. 创建规则：指标 `cpu`，条件 `>`，阈值 `80`，持续 `300` 秒
2. 关联邮件通知渠道
3. 当 CPU 持续 5 分钟超过 80% 时，收到邮件告警
4. 登录面板查看仪表盘和容器管理，定位高 CPU 进程
5. 处理后 CPU 下降，告警自动恢复

### 场景二：磁盘空间不足预警

1. 创建规则：指标 `disk`，条件 `>`，阈值 `85`，持续 `60` 秒，级别 `warning`
2. 创建第二条规则：阈值 `95`，级别 `critical`
3. 磁盘达到 85% 时收到警告，提前清理
4. 如未处理达到 95%，收到严重告警
5. 使用文件管理器清理大文件或日志
6. 在计划任务中配置定期清理

### 场景三：接入企业微信告警

1. 在企业微信中创建群机器人，获取 Webhook URL
2. 在面板中创建 Webhook 通知渠道，填入 URL
3. 配置请求体模板为企业微信格式
4. 点击"测试"确认群里收到测试消息
5. 将所有告警规则关联到此渠道
6. 服务器异常时企业微信群即时收到通知

### 场景四：多渠道分级告警

1. 创建邮件渠道（用于所有级别告警）
2. 创建 Webhook 渠道（企业微信，仅用于 critical 级别）
3. warning 级别规则只关联邮件渠道
4. critical 级别规则同时关联邮件和 Webhook
5. 普通异常通过邮件通知，严重异常即时推送
6. 避免低级别告警过多打扰
