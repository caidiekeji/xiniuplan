## 一、项目类型

服务器管理面板 / 后台管理系统（多页应用型，深色友好）。对标 1Panel / 宝塔，但视觉语言原创推导。

## 二、原创画面句

**"深夜数据中心里，机柜指示灯的有序闪烁被一块精密仪表盘翻译成可读的信号。"**

不是风格名，是一个可推导视觉语言的具体画面。

| **色彩** | 主色相=冷钢蓝(210°)；60%基底=深墨蓝灰；10%主强调=信号青绿 #1ba784（2026-09-10 用户指定，替换琥珀）；辅强调=信号青绿 | 数据中心深夜的冷色调环境 + 机柜指示灯的琥珀色（电源/活动灯）+ 青绿（正常运行灯）。#1ba784 为用户指定的主强调色。 |

## 五、签名元素

**"状态指示灯（Status LED）"** —— 每个关键数据/状态/列表行旁边有一个 6-8px 的微型指示灯圆点：
- 正常运行 = 青绿 `--acc2`，带微弱脉冲动画
- 警告 = 青绿 `--warn`（#1ba784，2026-09-10 起，项目无黄色）
- 异常/停止 = 红 `--err`
- 离线 = 灰 `--faint`

这是从"机柜指示灯"直接推导的视觉语言。换一个 brief（如电商、博客）这个元素就不成立。配合"精密仪表刻度"风格的等宽数字展示，构成云枢面板的识别签名。

## 八、动效四层方案

| 层 | 方案 | 从画面句推导 |
|---|---|---|
| L1 加载/入场 | 内容区块依次淡入上移（0.4s 交错）；骨架屏用"指示灯脉冲"占位 | 仪表盘通电后指示灯依次亮起 |
| L2 悬停/微交互 | 按钮/卡片：边框增亮 + 轻微上移(2px)，0.2s ease-out；指示灯 hover 时脉冲加速 | 指示灯靠近时更亮 |
| L3 滚动叙事 | 后台管理页少滚动，用 tab/分页切换；切换时内容淡入 | 仪表切换表盘 |
| L4 环境氛围 | 正常态指示灯微弱呼吸脉冲（3s）；仅此一处常驻动画 | 机柜指示灯的持续闪烁 |

**动效一致性**：微交互 `--t-fast: 0.2s`，状态切换 `--t-normal: 0.35s`，入场 `--t-slow: 0.5s`，缓动统一 `--ease: cubic-bezier(.4,0,.2,1)`。遵守 `prefers-reduced-motion`。

## 九、惯例打破决策

| 通用模板 | 本项目偏离 | 动机 |
|---|---|---|
| 后台面板 = 紫蓝渐变 + 玻璃拟态卡片 | 深墨蓝灰实底 + 细边框卡片 + 指示灯点缀 | 玻璃拟态在数据密集的后台降低可读性；实底+细边更接近"机柜面板"的工业精确感 |
| 深色后台 = 纯黑底 + 单一蓝色强调 | 深墨蓝灰(带蓝相) + 青绿主强调 + 青绿状态色 | 纯黑+蓝是终端模板；青绿 #1ba784 来自机柜指示灯，有项目专属感 |
| 大圆角卡片（16px+） | 克制圆角（sm=4px, md=8px） | 机柜/仪表盘是精密矩形，大圆角会消解工业感 |
| 状态用文字标签 | 状态用"指示灯圆点 + 文字"双表达 | 指示灯是签名元素，圆点比纯文字更接近设备面板 |

## 十、排版/细节设计思维要点

- **主角**：Dashboard 的资源数值（等宽大字）是首屏主角，趋势图是配角，操作日志是辅助
- **动线**：左侧导航 → 顶栏面包屑 → 内容区 StatCard 行 → 图表 → 日志表，Z 型阅读
- **节奏**：StatCard 四连排（紧凑）→ 图表区（宽松）→ 日志表（紧凑），松紧交替
- **对比**：数值用 display 级等宽大字 vs 标签用 caption 级小字，拉开 3 级层级
- **感知权重**：高感知元素（数值、指示灯、CTA）精修；低感知（分隔线、占位文字）克制
- **删减**：不做无意义的装饰性渐变/光斑；每个色块都承载信息

## 十二、Token 系统摘要

- 色彩：60-30-10 双主题 + 语义色（ok/warn/err）
- Type Scale：display/headline/title/body/caption 五级，数字用等宽字体
- 间距：4px 基准，--space-1..8（4/8/12/16/24/32/48/64）
- 圆角：sm=4px / md=8px / lg=12px（克制）
- 阴影：sm/md/lg 三档，深色主题用微光阴影
- 动效：--t-fast 0.2s / --t-normal 0.35s / --t-slow 0.5s，--ease 统一
- 断点：sm=640 / md=1024 / lg=1440
- z-index：base=0 / sticky=100 / modal=1000

## 响应式规范（2026-09-10 移动端适配修复后固化）

- **断点**：沿用 token `--bp-sm: 640px / --bp-md: 1024px`；媒体查询统一用 768px（布局堆叠）、640px（双列降单列）、480px（四列降一列/紧凑）。
- **表格**：一律走 `DataTable` 组件（自带 scroll-x=700 横向滚动兜底），禁止页面直接用 NDataTable。
- **弹窗**：宽度一律 `min(设计宽, 92vw)`，或用 token `--modal-width-md/lg`（已内建 min()）；禁止裸 px 宽度。
- **栅格**：NGrid 用响应式字符串 `cols="1 s:2 l:4"` + `responsive="screen"`；CSS grid 多列卡片用 `repeat(auto-fit, minmax(N, 1fr))` 或补 640/480 单列档。
- **双栏面板**（键列表+详情、侧栏+内容）：768px 以下 `flex-direction: column` + 侧栏/详情 `width: 100%` + 限 max-height。
- **全局兜底**：body `overflow-x: hidden`；768px 下弹窗 max-width 钳制、filter-bar/tab-toolbar 换行。
- **桌面不受影响**：所有修复都是"移动端追加媒体查询"或"min() 钳制"，桌面端数值不变。

## Tab 时序规范（2026-09-10 修复后新增）

- NTabPane 默认 display-directive=if：切走即卸载、切回重新挂载。
- 子 Tab 组件必须在自身 onMounted 里加载数据，禁止只依赖父组件 watch(activeTab) 里调用 ref 方法——watch 默认 pre-flush，触发时新面板尚未挂载，ref 为 null 会被 `?.` 静默跳过，表现为"切回 tab 后列表为空"。
- 父组件如需在切 tab 后调用子组件方法，watch 回调先 `await nextTick()`。

## CSS Token 管理规范（2026-09-10 全量核查后）

- 全站 `<style>` 块与样式文件的**硬编码颜色已清零**（白 #fff 与 tokens.css 自身除外）。
- 新增组件层 token：`--overlay`（遮罩）、`--log-viewer-bg/text`（日志查看器）、`--acc3-hover`（亮暗两套）。
- **允许保留的硬编码**（均为合理场景，勿"修复"）：
  1. App.vue 等处的 `tokens.value.xxx || '#hex'` 形式——这是 JS 侧读取 CSS 变量失败的**兜底常量**，值与 token 一致；
  2. appstore/plugins `iconColors` 数组——图标多彩调色板是**数据**，非主题色；
  3. main.ts 无障碍拦截页的内联 HTML——挂在 Vue 应用之外，token 不可用。
- 新增颜色时一律先查 tokens.css，没有相近 token 就先加 token 再用。
